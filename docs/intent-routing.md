状态：规则与生成式分类已接入测试页。本文负责 `/devtools/intent-routing` 的识别对照与评测；同一页面的完整医疗咨询试跑见 [medical-consultation-routing.md](./medical-consultation-routing.md) 第 6.3 节。正式路由、医疗 agent 和发布门槛也以该文档为准。

## 两份计划的执行顺序

1. 先按本文第 2—5 节完成识别实验：核对现有实现，补齐规则与生成式模型的单句对照、批量评测、错例及运行配置记录。以本文第 3、5 节验收；不要把实验结果接入正式聊天。
2. 再按 [医疗咨询总设计](./medical-consultation-routing.md) 第 7、8 节核验评测基线，实施正式逐轮路由、医疗回答及用户配置。是否启用医疗生成由独立验收决定，不能以本页开发集成绩代替。
3. 正式路由和回答逻辑可复用后，按总设计第 6.3 节及阶段 D 扩展**同一个页面**：增加多轮输入、完整试跑、逐步结果和错例回填。保留本文的识别对照能力；完整试跑不得写入正式会话或触发外部副作用。

开发时分别核对两份文档对应阶段的完成标准。若页面要求与正式路由行为冲突，以总设计的运行契约为准，并在测试页展示实际路由结果。

## 1. 范围与当前行为

测试页位于 `apps/stage-web/src/pages/devtools/intent-routing.vue`，只在开发环境提供。它直接调用分类器，不写聊天会话，也不改变正式回复。页面按第 7.2 节分成**四个页签**，共用输入在页签上方：**规则** / **生成式模型**（只有这里能编辑分类提示词草稿）/ **双列对照**（同一份输入一次跑两种方法，两列并列，每列显示自己实际收到的文本、失败与耗时）/ **完整试跑**（正式路由 + 咨询回答）。配置摘要与共用输入（当前消息 + 上文）在页签之上，批量评测、结果追溯在页签之下，本次记录作为附录。

双列对照的每一列独立失败：模型连不上不掩盖规则说了什么；输入或配置改变后，旧结果会出现「已经变了，重新跑一次」的提示。完整试跑调用 `previewMedicalTurn()`，走正式路由与提示词组装，用页面“上文”做多轮输入，读页面提示词草稿，结果只留在页面上。测试页的模型列取当前聊天 Provider 与模型；只有选中 DeepSeek 时，这列才调用 DeepSeek。

正式聊天与测试页分开：`VITE_MEDICAL_GENERATION` 关闭时，规则决定医疗固定回复、急症指引或普通聊天；开启时，急症规则先行，其余消息由当前聊天模型分类。测试页的任何结果都不参与 `chat.ts`、`routeMedicalTurn()`、角色卡设置或聊天工具调用。

| 测试方式 | 当前职责 | 是否改变正式聊天 |
| --- | --- | --- |
| `rules` | 运行关键词和急症规则 | 否 |
| `model` | 请求当前聊天模型输出分类 JSON | 否 |
| `compare` | 并列比较规则与生成式分类 | 否 |

原阶段二的目标是比较规则与 DeepSeek。当前保留这两种方法，不做第三种分类器。

## 2. 分类契约与代码位置

`packages/stage-ui/src/libs/intent/contract.ts` 拥有 `IntentDecision`：`decision` 为 `medical | chat`，另有 `scene`、`evidenceCodes`、`source` 和 `classifierVersion`。规则结果的 `source` 为 `rule`，生成式模型有效结果为 `model`，请求失败或输出无效为 `fallback`。评测时，`fallback` 不是一次有效的医疗判断，不能按返回的保守标签计为命中。

| 位置 | 职责 |
| --- | --- |
| `packages/stage-ui/src/libs/intent/classify-rules.ts` | 规则分类和急症词匹配 |
| `packages/stage-ui/src/libs/intent/classify-model.ts` | 生成式分类请求、JSON 解析和失败原因 |
| `packages/stage-ui/src/libs/intent/classify.ts` | 原有 `rules`、`model`、`compare` 模式 |
| `packages/stage-ui/src/libs/intent/evaluate.ts` 与 `fixtures/` | 标注样本、分组、召回与误判统计 |
| `packages/stage-ui/src/libs/intent/preview.ts` | 完整试跑：正式路由与回答，只作用于页面 |
| `packages/stage-ui/src/libs/intent/report.ts` | 可导出的评测报告与发布门槛对照 |
| `apps/stage-web/src/pages/devtools/intent-routing.vue` | 参数输入、单句对照、批量报告和错例展示 |

生成式分类使用当前聊天 Provider 的 `chat(model)`，关闭 reasoning，以非流式方式请求一个 JSON 对象。分类提示词可在测试页试改；草稿只供试验，不能直接变成正式配置。失败要显示原因并单列，不把 JSON 或失败标签当作用户回复。

## 3. 页面交互与验收

| 操作 | 页面展示 | 验收要求 |
| --- | --- | --- |
| 单句对照 | 规则与当前生成式模型两列；判定、来源、证据码、失败原因和耗时 | 每列注明“未运行”或失败；任何一列失败不阻止另一列 |
| 批量评测 | 医疗召回、闲聊误判、失败率、分母、耗时和逐条错例 | 两种方法使用相同标注集；未标注样本跳过且不进分母；失败不计为正确 |
| 完整试跑 | 识别结果、正式路由、咨询回答或固定回复 | 不写正式会话、不触发外部副作用；回答质量不计入分类准确率 |

页面须提供「回填」：把某条错例的当前消息与上文写回共用输入，便于复现。对每次运行记录样本集版本、模型、分类提示词摘要和运行环境；任一项变化后，旧报告标为不可直接比较。

## 5. 开发顺序与检查

1. 核对规则与生成式分类的输入契约，确认页面显示的就是分类器实际发送的文本与上文。
2. 固定样本集版本与配置快照；验证输入、模型或提示词变化后旧结果会标为不可比较。
3. 对同一句和同一标注集展示两种方法的结果及逐条错例，并支持回填复现。
4. 只用开发集调提示词；用未参与调参的样本重新验收。

单元测试用模拟模型响应，覆盖非法 JSON、超时、空响应、回退计分、上下文追问与计分口径。真实服务测试只使用合成或已脱敏样本。运行相关 Vitest、受影响包的 typecheck 和仓库 lint；评测页的启动和页面交互另做人工核验。

## 6. 后续：是否接入正式路由

本节仅记录候选流程，当前测试页不会执行：

```text
用户消息入队
  → 急症规则命中：立即给急诊指引
  → 否则由当前生成式分类器判断医疗 / 闲聊
  → 分类失败：安全兜底，不按规则的普通医学词命中冒充有效判断
```

急症规则必须先于模型运行。不能把失败回退标签计为模型命中。正式策略由部署配置控制，不能由测试页的提示词草稿、角色卡或普通用户设置直接改变。

是否接入正式路由，按 [医疗咨询总设计](./medical-consultation-routing.md) 第 7 节的发布门槛决定：医疗召回 ≥95%、闲聊误判 ≤5%、逐轮分类失败率 ≤1%、人工复核急症集全部命中、分类 P95 ≤2 秒。独立验收集至少 300 条，其中至少 150 条医疗、100 条闲聊，并覆盖短句、就医流程和 ASR 错字。未达标时保持当前固定医疗回复与部署开关策略。

## 7. 下一步：统一对照与评测闭环（待开发）

本节承接现有页面，不覆盖第 1—6 节的分类契约和正式路由门槛。当前页面已有单句分类、规则与生成式模型对照、批量报告，以及完整医疗咨询试跑。以下工作分成两个交付阶段：先让两种分类方法的结果易于比较，再增加样本管理、标注和历史报告。完整咨询试跑继续作为测试台上的独立操作，不计入分类器对照。

### 7.1 为什么要重构当前页面

现有功能可以单独使用，但一次评测要在不同区域操作和阅读结果。优先重构页面交互、结果组织和运行记录，不重写已存在的规则或生成式分类器。

| 当前表现 | 给评测带来的问题 | 重构方向 |
| --- | --- | --- |
| 顶部 `rules`、`model`、`compare` 三个按钮与页签并存 | 两套控件选择同一件事 | 页签是唯一的方法控件 |
| 规则与生成式报告分别运行、分别展示 | 指标和逐条错例难以按同一批样本比较 | 统一逐条结果及统计口径；每列保留自身失败与耗时 |
| 输入、上文、模型与提示词可在运行后继续变化 | 旧结果可能看起来仍属于当前输入或配置 | 每次结果绑定输入与配置快照；变化后明确失效或重新计分 |
| 分类对照、批量表格和完整咨询试跑都在一条长页面 | 测试者难以区分「分类准确率」与「最终回答是否合适」 | 测试台突出分类对照；完整试跑单列为路由与回答检查；样本和报告迁到二级页面 |

重构时先整理页面内的输入、运行状态和结果呈现，再拆分有独立职责的页面或组件。分类、计分和正式路由仍由各自现有模块负责；页面不复制业务判定。

### 7.2 页面结构与入口

侧边栏保留一个「意图评测」入口。在该入口内使用带独立地址的二级导航，避免把所有功能继续堆在一个长页面里。三个页面共享当前样本集版本和运行配置摘要：

| 二级页面 | 负责的操作 | 首批开发范围 |
| --- | --- | --- |
| 测试台：`/devtools/intent-routing` | 共用单句与上文输入；按页签测试规则、当前生成式模型，查看双列对照与完整咨询试跑 | 先重排现有功能；每个页签只展示自己的设置与结果 |
| 样本集：`/devtools/intent-routing/datasets` | 查看、录入、导入、分组、标注与复核样本 | 第二阶段；标注放在样本详情中，不单建侧边栏入口 |
| 运行与报告：`/devtools/intent-routing/runs` | 选择固定版本批量测试，查看进度、统计、错例及历史运行 | 第二阶段；错例可带上文返回测试台或样本详情 |

路由仅表示产品信息结构；实现时核对现有文件路由的生成规则，不因本节的地址示例另建一套 Devtools 入口。

进入「意图评测」时，从数据库读取最近一次已保存的批量运行，在测试台顶部展示结果摘要、运行时间、测试集和两种方法的状态；点摘要进入完整报告。若当前样本或配置已变化，摘要保留但标明「历史结果，需重新运行」。没有记录时显示空状态，不自动请求模型。进入「运行与报告」默认打开最近一次报告，并可切换历史运行。当前单句测试记录只留在页面会话中；是否需要单独保存单句历史，待内测使用后决定。

测试台内使用 Tab 组件切换功能，不把每种分类方法做成侧边栏菜单。共用输入放在页签上方；各页签只放本功能的操作、设置和结果：

| 测试台页签 | 专属内容 |
| --- | --- |
| 规则 | 规则判定、命中依据和耗时；不展示模型提示词 |
| 生成式模型 | 当前 Provider／模型、分类提示词草稿、模型输出、失败原因和耗时；只有此处编辑分类提示词 |
| 双列对照 | 用同一份输入查看或运行两种方法；并列显示判定、失败及实际输入差异；不在这里编辑各方法的专属配置 |
| 完整试跑 | 独立展示识别、正式路由和咨询回答；不把回答质量算进分类准确率 |

切换页签不修改输入或抹掉已完成的运行。输入或相关配置变化后，受影响的旧结果标为过期；返回「双列对照」时不能把旧列当成新判断。页签仅组织测试台内部功能；样本集和运行报告仍是上表的二级页面。

「双列对照」页签打开时先展示与当前输入、上文和配置快照匹配的已有结果，不因切换页签自动调用付费模型。需要新结果时，由用户点击「运行对照」；运行前显示预计请求数，运行中展示各列状态。单独方法页签产生的结果只有快照完全一致时才能复用。无法运行的一列单独标记失败或未运行，不阻止其他列完成。

### 7.3 先完成双列对照

测试台只保留一份当前输入：当前消息、按角色和顺序记录的必要上文，以及本次配置。在「双列对照」页签运行后，集中展示规则与当前生成式模型两列。每列显示「医疗／闲聊／失败／未运行」、耗时和可解释信息；模型回退不能显示为有效的医疗命中。生成式列使用实际选中的 Provider 和模型名，不固定写成 DeepSeek。

共享运行配置目前只同步 Provider ID 和模型名，不同步各浏览器的 Provider 连接。用管理员选择的自定义 Provider 做评测前，须在普通用户环境验证该模型确实可调用；否则报告中的模型名不能证明该配置可供所有用户使用。服务端凭据不得写入评测报告或公开的共享快照。

规则和生成式模型的输入能力不同，页面要展示各列实际收到的文本与上文。任一输入、提示词、模型变化后，旧结果不得继续显示为同一次可比较的结果。完整咨询试跑显示路由与回答，不混入分类准确率。

批量结果统一为「一行样本，两列判定」，可按分组、标准答案、分歧、医疗漏判、闲聊误判和失败筛选。统计并排显示两种方法的医疗召回、闲聊误判、失败率、分母和耗时；没有运行的一列不显示零分。第一阶段沿用现有开发样本，完成同屏对照、结果失效和统一错例筛选，不开放样本编辑。

### 7.4 再建立样本与标注闭环

```text
收集合成或脱敏样本 → 人工标注与复核 → 选择当前测试集
  → 选择方法和配置运行 → 查看统计、分歧与错例
  → 返回测试台复现，或返回样本详情修正 → 再运行
```

每条样本至少有稳定 ID、当前消息、必要上文及其角色、分组、人工标签、标注状态和来源说明。**人工标签可以为空**：未标注样本可以保存、参与列表与导入，但批量运行跳过它们，且不计入任何指标分母。内测期间，所有能使用开发工具的人员都可直接编辑标签和复核样本；不增加复核角色、修改人日志或手动冻结流程。模型输出可帮助定位待复核样本，不能自动写成标准答案。批量导入先核对格式、重复样本和缺失上文，再由人确认入库。正式发布验收前再确定是否需要更严格的复核规则。

开发集可用于调提示词；独立验收集只用于最终检验。当前 92 条样本只作为开发集起点，不因加入管理页面而自动成为独立验收集。

一次批量运行记录模型、分类提示词摘要、样本集版本、配置指纹。报告保存样本 ID、逐条判定、当次统计、指标分母、失败原因、开始时间及运行状态；不额外复制样本正文或人工标签。内测期间可直接修改测试集再运行；旧报告只表示当时算出的结果，样本改动后不保证能按旧报告复现，页面提示重新运行。持久化内容只使用合成或脱敏文本；不记录密钥或用户原始医疗消息。

样本、人工标签、逐条运行结果和报告均存数据库，由应用接口读写；浏览器本地存储不作为这些数据的权威来源。运行期间的临时进度可留在页面状态中，刷新后仍须从数据库恢复已保存的运行状态。

服务端落点（已实现，待测试）：`server/apps/api` 挂载 `/api/v1/intent-eval`，沿用现有资源 API 的形状。

| 路由 | 作用 |
| --- | --- |
| `GET /collections`、`POST /collections` | 列出与新建样本集（名称 + 用途 `development`／`acceptance`） |
| `POST /samples/import` | 批量导入（单条请求上限 500 条，一条坏行整批拒绝） |
| `PATCH /samples/:id`、`DELETE /samples/:id` | 改标签或复核状态；删除是软删除，已跑过的运行保留自己的快照 |
| `GET /runs?limit=`、`GET /runs/:id` | 列出与读取运行（默认 20 条，最多 100） |
| `POST /runs` | 开一次运行，固定样本集版本、模式、`configKey`、模型与提示词摘要 |
| `PATCH /runs/:id` | 上报进度与结果；进入终态时自动写 `finishedAt` |

### 7.5 开发与验收顺序

| 顺序 | 交付物 | 验收点 | 状态 |
| --- | --- | --- | --- |
| 1 | 测试台方法页签与双列对照 | 规则页签不显示提示词，生成式页签才可编辑提示词；同一输入可在对照页签看到两列结果；改输入后旧列不再冒充新结果 | 待测试 |
| 2 | 统一的逐条批量结果 | 同一批样本可筛出分歧和错例；指标分母、未标注跳过数与输入差异清楚可见 | 待测试 |
| 3 | 样本集与人工标注 | 可录入、导入、编辑标签（含未标注）和复核；不要求手动冻结或记录修改人 | 待测试（服务端 CRUD + 样本集页面） |
| 4 | 运行历史与错例回流 | 最新报告的错例可用当前样本回填；修正后重新运行。旧报告保留统计与判定，不承诺复现已修改的样本 | 待测试（错例回流、运行写入、运行历史与详情页面） |
| 5 | 简易评测报告 | 一份可导出的文档，列出两列指标与分母、分组统计、错例摘要，并逐项对照发布门槛给出结论 | 待测试 |

第 1 项的当前实现：页签用 `SelectTab`，`tab` 是唯一的方法控件，`mode` 由 `watch(tab)` 同步，所以一次运行不会被标成页签没显示的方法；共用输入在页签上方；分类提示词草稿只在生成式页签出现；双列对照用 `runThreeWay()` 一次跑规则与生成式，各自保留失败；`composeClassifierUserText()` 让页面显示与分类器实际发送完全一致的文本；`threeWayStale` 比对消息、上文、模型与提示词摘要，任一变化即提示旧结果不可比。

第 2 项的当前实现：`EvaluationReport.cases` 保留每个样本的两侧判定，页面据此得到 `batchRows`；筛选覆盖全部 / 分歧 / 医疗漏判 / 闲聊误判 / 失败；指标表按方法并排给出召回、误判、失败率与**分母**；每行显示标答、两列判定与是否分歧，并带出该样本的上文。未标注样本不进 `batchRows`。

第 3 项的已落地部分：服务端样本 CRUD 与样本集页面；`expected` 可空（迁移 `0030`）；未标注样本可保存、可导入、可在页面显示，批量评测跳过。

第 4 项的运行历史部分（已实现，待测试）：`apps/stage-web/src/pages/devtools/intent-routing/runs.vue`，地址 `/devtools/intent-routing/runs`。列表可切换最近 20/50/100 次，选中后看到配置指纹、提示词摘要、起止时间、提前结束原因，以及两列指标与逐条结果。页面只读：运行是不可变记录。

第 5 项的当前实现：`packages/stage-ui/src/libs/intent/report.ts` 的 `buildEvaluationMarkdown()` 把当前表格的数据渲染成 Markdown——两列指标与分母、分组统计、分歧前 10 条、以及逐项对照发布门槛的 ✅/❌ 与结论句；样本数少于 300 条时自动加「只作开发集诊断、不能作为上线依据」。门槛数字集中在 `releaseGates`。P95 耗时与医疗回答人工审核不在报告内，结论句会写明。

### 7.6 样本集管理：内测版实施规格

本节细化第 7.5 节第 3、4 项。先实现能录入、改标签、选集合并运行的管理页；不加入修改人日志、手动冻结、审批流或通用标注平台。数据库复用现有 `server/apps/api` 的 PostgreSQL、Drizzle 和 Hono 接线。无后端连接时页面显示不可用原因，不用浏览器本地存储冒充数据库。

**已落地**

- 样本增删改查、批量导入、软删除；按登录用户隔离。
- 人工标签可以为空（`expected` 可空），未标注样本可保存、可导入、可在列表显示；批量运行跳过它们，且不计入任何指标分母。
- 样本集页面：单条新增、JSON 导入、改标答、标记复核、删除；表格显示分组、上文、来源、标答与复核状态。
- 样本集（集合）：新建／改名／两步确认删除集合、按集合过滤样本；所选集合存在 localStorage，测试台共用并按它取样本。
- 样本详情：datasets 页「编辑」打开行内编辑区，可改当前消息、**按角色与顺序编辑多轮上文**（最多 10 轮）、分组、标答（可空）、复核与来源；保存后刷新列表并提示"已有报告需重跑"。
- 上文按数组存储：`intent_samples.context`（jsonb），迁移 `0032` 把旧的单条 `previous` 回填成一条 user 上文；批量评测按角色读取全部上文，不再丢弃 assistant 轮次。
- 导入预校验：先「预览」再「确认写入」；逐行报告缺消息、未知分组、非法标答、非法上文轮次，重复项单独列出且不写入；有任何不合法行时整批不写。
- 运行记录：写入、历史列表与只读详情页。
- 评测报告导出（Markdown）与发布门槛逐项对照。

页面目标：

| 区域 | 操作与反馈 |
| --- | --- |
| 集合列表 | 显示名称、用途、样本数、已标注数和最近一次运行入口；可新建、改名、选择集合。空库时引导新建或导入内置样本 |
| 样本列表 | 按关键词、分组、标签和复核状态筛选；每行显示 ID、消息摘要、标签与是否有上文。点一行打开详情，不在长表格内编辑正文 |
| 样本详情 | 编辑当前消息、按顺序编辑上文角色与内容、分组、标签和复核状态；保存后列表立即更新。改标签或正文后提示已有报告需要重跑 |
| 导入 | 首版支持现有样本结构的 JSON；先预览总数、缺字段、重复 ID 和无效标签，再确认写入。整批校验失败不写入半批数据 |
| 删除 | 删除样本或空集合前确认；有历史报告时仍可删除样本，但旧报告只能显示样本 ID 和当时判定。首版不提供恢复功能 |

输入与上文只接收合成或已脱敏内容。相同消息和上文的重复项给出提示，由人决定是否保留。模型判定可从报告带入详情供人工参考，但不能自动写入人工标签。

接口与边界：在现有 `intent-eval` 接口上增加集合的列表／创建／改名／删除，以及按集合查询样本；样本路由补齐集合归属。接口校验标签、分组、上文角色、输入长度和集合归属；导入须整批成功或整批失败。前端只通过接口读写。现有 API 按 `userId` 隔离样本，如需多人共用一个集合，须先明确共享范围并调整查询边界，不可只在前端放开按钮。

批量评测从所选数据库集合取**已标注**样本；未标注样本显示数量并跳过。集合选择与预计模型请求数已接入页面，空集合按零条处理并阻止空运行。选定集合后显示将运行的样本数和预计模型请求数，再由用户主动开始。

实施顺序与完成标准：

1. 接通现有 API 与数据库，新增集合和样本的存取边界；用接口测试覆盖校验、分页、导入事务和空库。
2. 实现集合列表、样本列表与详情编辑；验证新增、改标签、带角色上文和删除后的页面状态。
3. 提供内置 92 条样本的幂等导入；确认重复导入不覆盖手工修改，也不把它们标作独立验收集。
4. 让批量评测读选中的数据库集合；核对已标注数、指标分母与上文输入，运行前明确显示预计请求数。
5. 将最近一次报告与历史报告存数据库；刷新后仍能看到最近结果。样本变动后旧报告显示为历史结果，不再用当前标签重算。
