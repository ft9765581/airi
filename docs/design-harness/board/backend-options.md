# 后端简化方案比较

| 决策点 | 首版方案 | 暂不采用 | 原因 |
| --- | --- | --- | --- |
| 服务边界 | 扩展现有资源 API | 新建 MCP、知识库和 Worker 微服务 | 现有 API 已有全部基础设施；新增服务会增加部署与一致性成本 |
| 用户模型 | 每个资源直接使用 `owner_id` | 首版引入组织、成员和角色系统 | 当前需求是多用户，不是团队协作；直接所有权足够形成可靠隔离 |
| MCP 传输 | 远程 Streamable HTTP | 云端运行任意 `stdio` | 远程 HTTP 可做超时、域名与网络出口控制；任意进程执行风险过高 |
| 知识库存储 | PostgreSQL 文本、全文索引和向量 | 独立向量数据库 | 当前 PostgreSQL 已有向量扩展；单库事务能简化删除和权限检查 |
| 后台任务 | API 内部 Worker 加数据库任务表 | Redis 队列服务 | 文档规模较小时，一个可恢复任务表已经足够；后续可保持任务契约并替换执行器 |
| 文件格式 | 文本与 Markdown | 首版支持 PDF、Office 和网页 | 文档解析会引入较多依赖和安全面，且不影响检索核心闭环 |

## 需要产品确认的后续范围

- 知识库是否要多人共享。如果需要，新增 workspace 与 ACL，而不是复用 `owner_id`。
- MCP 是否允许用户填写任意公网 URL。如果不允许，改用管理员维护的连接目录。
- 首版是否必须处理 PDF。如果必须，文档解析应进入隔离 Worker。
